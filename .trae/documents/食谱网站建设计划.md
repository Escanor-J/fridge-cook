### `scripts/preprocess.py` 实现要点

**1. CSV 读取**
- 优先 UTF-8，失败回退 GBK/GB18030
- 使用 `pandas.read_csv`

**2. 数据筛选**
- `status == 1`
- `title` 非空（notna 且 strip 后非空）
- `yl` 非空
- 按 `id` 升序排序后取前 2000 条

**3. 数据清洗**

通用：
- 所有字符串字段 strip 首尾空白和 `\r\n`
- NaN → NULL

`#` 号分隔字段（yl/fl/steptext/steppic）：
```python
def split_hash(s):
    if not s or pd.isna(s): return []
    return [item.strip() for item in str(s).split('#') if item.strip()]
```
- yl 与 fl 按索引 zip，fl 不足补空字符串
- steptext 与 steppic 同理

食材名清洗：
- 去括号及内容：`盐（适量）` → `盐`（正则 `[\(（].*?[\)）]`）
- 去前导数字和标点：`1. 花菜` → `花菜`（正则 `^[\d\s.、，,]+`）
- 保留 1~20 字符的项
- 去重时不区分全角/半角空格

分类字段 cid：
- 按中文逗号 `，` 或英文逗号 `,` 分割
- 每项 strip，过滤空串

难度映射（**更新版**）：
```python
DIFFICULTY_MAP = {0: '初级', 1: '中级', 2: '中级', 3: '高级'}
```

耗时归一化（**新增**）：
```python
def normalize_cost_time(s):
    # 提取所有数字（支持 '10-30分钟'、'10~30分钟'、'30'、'10分左右'）
    # 取范围内的最大值作为分档依据
    # 分档：<=15 → '15分钟以内'
    #       <=30 → '30分钟'
    #       <=60 → '1小时以内'
    #       >60  → '1小时以上'
    # 无法解析 → NULL
```

视频平台检测：按 spec 的 `detect_platform` 函数，videourl 原样保存。

**4. SQLite 输出**

建表 SQL 完全按 spec（recipes/ingredients/recipe_ingredients/recipe_categories/recipe_steps 五张表 + 索引）。

字段映射注意：
- `recipes.cost_time`：存归一化后的分档字符串（如 `30分钟`），不存原始混乱值
- `recipes.difficulty`：存原始整数（0/1/2/3）
- `recipes.difficulty_label`：存映射后的中文标签
- `recipes.main_category`：取 zid 字段
- `recipe_categories.is_main`：zid 对应的分类标记为 1，cid 中的标记为 0

**5. JSON 输出**

`ingredients_list.json`：按出现频次降序
`categories_list.json`：含 category/count/is_main

**6. 执行报告**（打印到控制台）
- 原始总行数
- 有效行数
- 实际写入行数（应为 2000）
- 食材去重后总数
- 分类总数
- 各视频平台数量统计
- 有缩略图的菜谱数量
- 评分异常值数量（grade 不在 0~5）

**7. 注意事项**
- 事务批量插入，单次 commit
- `INSERT OR IGNORE` 处理 ingredients 重复
- 幂等：先删 `recipes.db` 再重建

### 后端 API 设计（FastAPI）

**`GET /api/recipes`** — 菜谱列表/搜索
- 查询参数：
  - `keyword`（关键词搜索 title/description）
  - `difficulty`（0/1/2/3）
  - `cost_time`（归一化分档）
  - `category`（分类名）
  - `sort`（`view_count`/`fav_count`/`cook_count`，默认 `view_count`）
  - `page`、`page_size`（默认 1、12）
- 返回：`{ items: [...], total, page, page_size }`

**`GET /api/recipes/{id}`** — 菜谱详情
- 返回：菜谱主信息 + 食材列表 + 步骤列表 + 分类列表

**`GET /api/recipes/match`** — 冰箱模式（食材匹配）
- 查询参数：`ingredient_ids`（逗号分隔的食材 ID）
- 逻辑：
  ```sql
  SELECT recipe_id, COUNT(*) as matched
  FROM recipe_ingredients
  WHERE ingredient_id IN (...)
  GROUP BY recipe_id
  ```
  再在 Python 中计算 `匹配度 = matched / 该菜谱食材总数`，按匹配度降序排序
- 返回：`{ items: [{ recipe: {...}, match_ratio, matched_count, total_count }] }`

**`GET /api/ingredients`** — 食材列表（冰箱模式用）
- 返回 `ingredients_list.json` 内容（支持 `?keyword=` 过滤）

**`GET /api/categories`** — 分类列表
- 返回 `categories_list.json` 内容

**CORS**：允许 `http://localhost:5173`（Vite 默认端口）

### 前端实现

**技术栈**：Vite + React 18 + React Router + Tailwind CSS + axios

**页面路由**：
- `/` → Home（首页）
- `/fridge` → FridgeMode（冰箱模式）
- `/recipe/:id` → RecipeDetail（详情页）

**Home 页**：
- 顶部：LOGO + 搜索框 + 分类导航
- Hero 区："今天吃什么？" + 冰箱模式入口按钮
- 筛选栏：难度 · 耗时 · 分类 · 排序
- 菜谱卡片网格（封面图、菜名、难度 badge、耗时 badge、热度）
- 分页

**FridgeMode 页**：
- 食材标签云（从 `/api/ingredients` 加载，按频次显示）
- 点击食材标签选中/取消，支持搜索过滤
- 实时调用 `/api/recipes/match` 显示匹配结果
- 结果按匹配度排序，显示匹配度百分比

**RecipeDetail 页**：
- 封面图（大）+ 视频按钮（有视频时弹出 iframe）
- 菜名 + 简介 + 难度/耗时 badge
- 食材清单（两列：食材 | 用量）
- 步骤（序号 + 文字 + 步骤图）
- 小贴士

**VideoEmbed 组件**：
- youku：直接 iframe embed
- bilibili/tudou/iqiyi/tencent：按平台规则处理
- other/无视频：隐藏视频区

**图片处理**：
- 封面图、步骤图直接用数据集中的 URL（`cp1.douguo.net` 等）
- 加载失败时显示占位图

### 启动方式
- 后端：`cd backend && pip install -r requirements.txt && uvicorn main:app --reload --port 8000`
- 前端：`cd frontend && npm install && npm run dev`（端口 5173）
